# Character / UI 再構成 実装手順

## 目的
- UIシーンを中央制御プロセスにする
- キャラクター1体ごとにCharacterプロセスを分離する
- 個々のキャラクター制御をCharacterCompanionへ移す
- STT、TTS、LLM、ウィンドウ追跡をUI側へ集約する

## 変更後の責務

### UIプロセス
- キャラクター群の総合管理
- Characterプロセスの起動、監視、再起動、終了
- characterId とプロセス情報の管理
- ウィンドウ位置、フォーカス、前面化の把握
- STT、TTS、LLM の中央制御
- キャラクターごとのイベント配送

### Characterプロセス
- 1体分のキャラクター制御
- モデル読み込みとAnimator初期化
- 落下、着地、歩行、ドラッグ、スクロール
- 吹き出しの表示と個体状態の更新
- UIから受け取ったウィンドウ情報に基づく動作

### CharacterManager
- UIシーン上の総合管理コンポーネント
- CharacterCompanionの登録、解除、検索
- 生成、破棄、再生成の委譲
- アクティブキャラの選択とルーティング
- 個体制御そのものは持たない

### CharacterCompanion
- 個体ごとの制御本体
- 現在のCharacterManagerから移管する単体制御ロジックの受け皿

## 実装順

### 1. 境界を定義する
- 共通データ型を決める
- characterId、CharacterState、WindowSnapshot、BubbleCommand、VoiceRequest を定義する
- UIとCharacterの通信形式を先に固定する

### 2. 共通型を切り出す
- GroundAction のような個体制御依存型を CharacterManager から分離する
- AnimatorSync などの補助クラスが CharacterManager へ直接依存しない形にする

### 3. CharacterCompanion を新設する
- モデルロード
- Animator初期化
- 落下、着地、歩行、ドラッグ、スクロール
- 吹き出し表示
- 個体ウィンドウ追従
- 個体ごとの状態保持

### 4. CharacterManager を台帳型に縮小する
- 複数 CharacterCompanion の登録と解除
- アクティブキャラ選択
- 個体生成と破棄の委譲
- UIからの設定反映先決定
- 個体ごとのイベント配送

### 5. UI側の中央制御を作る
- Characterプロセス起動
- characterId ごとの管理台帳を作る
- ウィンドウ一覧と位置情報をUI側で取得する
- STT、TTS、LLM をUI側で受ける
- 必要なキャラクターへ配送する

### 6. 周辺依存を追従修正する
- CharacterSpeechBubbleUI の参照先を CharacterCompanion に切り替える
- TTSManager の対象参照を個別キャラ対応にする
- LLMProvider のルーティングをUI中央化に合わせる
- SettingsUIBridge を新しい所有関係に合わせる
- SelectModelDialog と各設定UIの参照先を見直す
- Animator補助クラスの参照を新しい共通型へ合わせる

### 7. シーンと起動経路を整理する
- UIシーンをメインの司令塔として扱う
- Characterシーンは個体プロセスとして起動する
- Build Settings と起動引数を整理する
- UIプロセスとCharacterプロセスの判定を統一する

### 8. 結合テストを行う
- 1キャラ起動
- 複数キャラ起動
- ウィンドウ追跡と着地判定
- 吹き出し表示
- STT、TTS、LLM のルーティング
- 終了処理と再起動

## 目安工数
- 仕様確定と通信設計: 1.5日から2.5日
- UI中央制御の骨格実装: 2日から4日
- CharacterCompanion への移管: 4日から7日
- ウィンドウ追跡と着地判定のUI集約: 2日から4日
- STT、TTS、LLM のUI集約: 3日から5日
- 周辺UIとAnimatorの追従修正: 2日から4日
- 結合テストと安定化: 3日から5日

## リスク
- 単一ポート前提の通信が複数キャラ化で破綻しやすい
- CharacterManager からの直接参照が多く、追従修正が多発しやすい
- ウィンドウ追跡の更新頻度が高すぎると着地判定が不安定になる
- STT、TTS、LLM の責務分離が曖昧だと再び境界が混ざる

## 推奨する進め方
1. 共通データ型と通信仕様を決める
2. CharacterCompanion を新設する
3. CharacterManager を総合管理へ縮小する
4. UI中央制御を入れる
5. 周辺依存を追従修正する
6. 最後に複数キャラで結合テストする

## 補足
- 最初は 1キャラ固定で UI 主導の最小ループを通す
- その後に複数キャラ化を足す
- 最初から完全な複数キャラ対応を狙うと修正範囲が広がる

## 作業チケット案

### A. 仕様と通信
- characterId の採番方法を決める
- UI と Character 間のメッセージ形式を定義する
- ウィンドウ情報、吹き出し指示、音声指示、状態通知の粒度を決める
- プロセスごとのポート割当ルールを決める

### B. 共通型の切り出し
- CharacterManager 依存の状態型を独立させる
- GroundAction 相当の列挙を共通化する
- WindowSnapshot、BubbleCommand、VoiceRequest を追加する
- AnimatorSync などの補助クラスの参照先を切り替える

### C. CharacterCompanion 新設
- モデルロードと初期化を移す
- Animator 初期化を移す
- 落下、着地、歩行、ドラッグ、スクロールを移す
- 個体ごとのウィンドウ追従を移す
- 吹き出し表示の所有権を移す

### D. CharacterManager 縮小
- キャラクター一覧の管理を追加する
- CharacterCompanion の生成と破棄を委譲する
- アクティブキャラの切替を実装する
- UIからの設定反映を個体へ配送する
- 個体制御ロジックを除去する

### E. UI中央制御
- UIプロセスを司令塔として起動する
- Characterプロセスを1体ごとに起動する
- Characterプロセスの死活監視を実装する
- ウィンドウ一覧と位置情報の収集を実装する
- STT、TTS、LLM の受け口をUIへ寄せる

### F. 周辺追従
- CharacterSpeechBubbleUI の参照先を更新する
- TTSManager の対象参照を更新する
- LLMProvider のルーティングを更新する
- SettingsUIBridge の反映先を更新する
- SelectModelDialog と UI 依存を更新する

### G. テスト
- 1キャラ起動確認
- 複数キャラ起動確認
- 着地とウィンドウ追従確認
- 吹き出し表示確認
- 音声認識と音声合成の中継確認
- 終了と再起動の確認

## 着手順の推奨
1. 仕様と通信
2. 共通型の切り出し
3. CharacterCompanion 新設
4. CharacterManager 縮小
5. UI中央制御
6. 周辺追従
7. テスト

## 再構成完了後の拡張ロードマップ

### 前提
- 本ドキュメントの「実装順 1-8」が完了していること
- UI中央制御、1キャラ1プロセス、複数キャラ起動、STT/TTS/LLM 連携が安定稼働していること

### フェーズ 0: 安定化と運用基盤
- 目的: 以降の機能追加に耐える状態へ固定する
- 実施内容:
	- 起動、終了、再起動、クラッシュ復旧の手順を標準化する
	- ログ設計を整理し、UI、Character、音声、IPC のトレースIDを統一する
	- IPC の後方互換ルールを決める
	- 負荷試験（キャラ数、ウィンドウ数、音声連続入力）を実施する
- 完了条件:
	- 連続稼働試験で重大クラッシュがない
	- 主要操作の再現手順と障害切り分け手順が文書化されている

### フェーズ 1: README 記載の主要UI機能を実装
- 目的: メニューダイアログと会話UIを実運用レベルにする
- 実施内容:
	- 右クリック対象キャラに紐づく設定ダイアログを完成させる
	- テキストAIチャットUIを実装し、キャラ指定で会話できるようにする
	- モデルインポート、モデル変更フローをUIから完結させる
	- 音声入力アイコン、認識結果表示、テキスト入力を統合する
	- 設定ファイルの編集反映と永続化の検証を行う
- 完了条件:
	- README の「UI（メインプロセス表示要素）」にある機能が一通り動作する
	- キャラ選択を伴う会話、モデル変更、設定変更が UI のみで完結する

### フェーズ 2: キャラクター行動拡張
- 目的: README の「今後の拡張」を具体機能として実装する
- 実施内容:
	- クリック時リアクション（表情、モーション、台詞）を追加する
	- LLM 応答内容に応じたアニメーション分岐を追加する
	- 読み上げ音声と連動したリップシンクを導入する
	- ウィンドウ上の挙動ルール（座り、寝そべり、歩き制限）を高度化する
	- 状態遷移と行動重みを外部設定化し、調整可能にする
- 完了条件:
	- クリック、会話、音声再生が連動してキャラ表現に反映される
	- 複数キャラ同時でも挙動破綻が起きない

### フェーズ 3: 複数キャラとマルチエージェント運用
- 目的: キャラごとに異なるエージェントと音声を割り当てられる状態にする
- 実施内容:
	- キャラごとのエージェント設定（モデル、プロンプト、温度など）を追加する
	- キャラごとの音声設定（speaker、style）を追加する
	- キャラごとのショートカット入力とルーティングを追加する
	- タスク管理、アラーム機能のキャラ単位アサインを設計する
- 完了条件:
	- キャラ単位で人格、音声、会話対象を分離できる
	- 同時対話時に文脈混線が発生しない

### フェーズ 4: 壁紙プロセス連携
- 目的: README 記載の壁紙プロセス構想を実装する
- 実施内容:
	- 壁紙側の出入口、着座点、寝そべり点を定義できる仕組みを作る
	- ディスプレイ単位で壁紙設定を分離する
	- キャラのディスプレイ間移動ルールを実装する
	- 壁紙プロセスSDKの最小APIを定義する
- 完了条件:
	- 複数ディスプレイ環境でキャラ移動と挙動が安定する
	- SDK利用者が最低限の壁紙連携を実装できる

### フェーズ 5: SDK と外部連携の公開準備
- 目的: README 記載の SDK 構想を開発者向けに提供する
- 実施内容:
	- キャラクター作成SDKの設定項目とサンプルを整備する
	- 壁紙プロセスSDKのサンプル実装を追加する
	- API仕様書を整備し、LangGraph 以外の接続例を用意する
	- バージョニング方針と互換ポリシーを定義する
- 完了条件:
	- サードパーティがドキュメントのみで最低限の統合を実現できる
